# auth-service — Claude guide

Central **Identity Provider (IdP)** for the migrated Pet Store. Port **8086**.
This is the **only token issuer** and the **only credential store** in the fleet. Every
other service is a pure *verifier*: it holds the public key (via `auth-client`) and can
validate a token but physically cannot mint one.

> Shared conventions (build/run, hexagonal layering, JMS, ports, parity rule) live in the
> repo skill `.claude/skills/petstore-dev/SKILL.md`. This file only covers what is specific
> to auth-service. See also `docs/LLD.md` (class + sequence design), root `DECISIONS.md`
> (ADRs), and root `docs/PARITY_AUDIT.md` (legacy behavioural baseline).

## Layout

Maven reactor with a parent POM and two sub-modules (`pom.xml` lists `client` **before**
`app` because `app` depends on `auth-client`):

```
auth-service/
  pom.xml                     parent (packaging=pom) → modules: client, app
  app/        artifactId auth-service  — the runnable IdP (Spring Boot 3.3.5, Java 21)
    src/com/petstore/authsvc/
      AuthServiceApplication.java      @SpringBootApplication
      web/AuthController.java          POST /auth/login  → issue RS256 token
      web/AccountController.java       POST /auth/accounts → provision credential
      service/AuthService.java         BCrypt credential check (only password-checker)
      security/JwtIssuer.java          mints RS256 with the PRIVATE key
      security/SecurityConfig.java     stateless; login/accounts/actuator public, else deny
      domain/AccountEntity.java        JPA @Entity for table `account`
      domain/AccountRepository.java    JpaRepository<AccountEntity,String> (port)
    resources/  application.yml, schema.sql, data.sql, auth-private-key.pem (gitignored)
    test/    web/AccountControllerTest.java (provision validation guards)
  client/     artifactId auth-client  — importable verify SDK (package com.petstore.auth.client)
    src/       JwtVerifier, AuthJwtFilter, AuthClient, AuthClaims, AuthPublicKey, PemKeys
    resources/ petstore-auth-public.pem  (bundled PUBLIC key)
    test/      JwtVerifierTest
  keys/       RSA keypair generated by ./generate-keys.sh (private_key*.pem gitignored)
```

Java package split: app = `com.petstore.authsvc`; client = `com.petstore.auth.client`.

## Build & test (this module only)

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
./generate-keys.sh                       # run once from repo root — creates the keypair
cd auth-service && mvn -q clean install   # builds client then app; installs both to ~/.m2
mvn -q -pl app test                       # AccountControllerTest
mvn -q -pl client test                    # JwtVerifierTest
```

`install` (not just `package`) is required because every verifier service imports
`auth-client:1.0.0` from `~/.m2`. Run the IdP with `mvn -pl app spring-boot:run` or via the
repo `./run-all.sh`.

## Invariants (do not break)

1. **Only auth-service holds the private key.** `JwtIssuer` loads
   `auth-private-key.pem` (PKCS#8) and is the sole `signWith(privateKey)` call anywhere.
   No verifier module may ever gain the private key.
2. **Verifiers only verify.** `auth-client` ships **only** `petstore-auth-public.pem`.
   `JwtVerifier`/`PemKeys` accept a `PublicKey` — there is no code path to sign.
3. **One account store for everyone.** All users — `USER` (customer), `SUPPLIER`, `ADMIN`
   (staff) — live in the single `account` table. Customer profile/cards live in
   customer-service; only *authentication* data lives here. `userId` is the stable opaque
   id other services reference; `user_name` is the primary key.
4. **RS256 everywhere.** Issue and verify both use RSA (jjwt `0.12.6`). Algorithm is
   inferred from the RSA key — never switch to HMAC (that would give verifiers the secret).
5. **Provision validation (legacy `UserEJB` parity).** `AccountController.provision`
   rejects with `400 invalid_request` when: userName blank/null, password null/empty,
   `userName.length() > 25`, `password.length() > 25`, or userName contains `%` or `*`.
   Duplicate userName → `409 duplicate_account`. These caps mirror `MAX_USERID_LENGTH` /
   `MAX_PASSWD_LENGTH` and must not be weakened — see `AccountControllerTest`.
6. **Passwords are BCrypt.** `PasswordEncoderFactories.createDelegatingPasswordEncoder()`
   (`{bcrypt}` prefix). `AuthService.authenticate` is the only place a password is checked.
7. **Stateless.** `SessionCreationPolicy.STATELESS`, CSRF disabled; it is a headless JSON API.

## Seeds

`schema.sql` creates the `account` table; `data.sql` MERGEs three seed logins (raw creds,
BCrypt-hashed): `j2ee/j2ee` (USER), `supplier/supplier` (SUPPLIER), `admin/admin` (ADMIN).
H2 in-memory DB (`jdbc:h2:mem:auth`), `spring.sql.init.mode=always`, `ddl-auto=none`.

## What it exposes / how others consume it

Endpoints (both public in `SecurityConfig`):

| Method | Path             | Purpose |
|--------|------------------|---------|
| POST   | `/auth/login`    | authenticate → `{token, tokenType:Bearer, userId, roles}` or 401 |
| POST   | `/auth/accounts` | provision a credential → 201 `{userId, role, status}` / 400 / 409 |

**Downstream services never call these directly with hand-rolled HTTP.** They import
`auth-client` and:

- Verify incoming requests by registering `AuthJwtFilter` in their `SecurityFilterChain`:
  ```java
  var verifier = new JwtVerifier(AuthPublicKey.bundled());
  http.addFilterBefore(new AuthJwtFilter(verifier), UsernamePasswordAuthenticationFilter.class);
  ```
  The filter reads a token from the `Authorization: Bearer` header **or** a `jwt` cookie,
  verifies the RS256 signature, and populates the `SecurityContext` with `ROLE_*` authorities
  from the token's `roles` claim. Invalid/expired → anonymous (context cleared, no 401 thrown).
- Log in / provision on the user's behalf via `AuthClient` (`login`, `provision`,
  `DEFAULT_BASE_URL = http://localhost:8086`).

Token claims: `sub` = userName, `uid` = stable userId, `roles` = list, `iat`/`exp`
(`auth.jwt.ttl-seconds`, default 3600). Adding a claim means editing `JwtIssuer.issue`
**and** `JwtVerifier.verify` + `AuthClaims` together — see `docs/LLD.md`.

## Key management

`./generate-keys.sh` (repo root) generates an RSA-2048 keypair, copies the PKCS#8 private
key to `app/resources/auth-private-key.pem` (gitignored) and the public key to
`client/resources/petstore-auth-public.pem` (committed — safe to share). Never commit the
private key; the repo is public and `.gitignore` blocks `private_key*.pem` and
`auth-private-key.pem`.
